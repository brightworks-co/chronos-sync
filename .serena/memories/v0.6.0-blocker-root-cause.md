# v0.6.0 vitest blocker — ROOT CAUSE 확정

작성: 2026-05-11 leader 직접 진단 (cmux pane).

## TL;DR
사용자 가설 (vitest mock factory의 ESM `.js` extension / `vi.hoisted` / `__esModule`) 모두 **오답**. 진짜 원인은 `tests/daemon.test.ts:76` 의 **`vi.resetAllMocks()`** 가 `mockReturnValue` 까지 wipe out 한 것.

## 진단 흐름

1. 에러: `Cannot read properties of undefined (reading 'refuse')` — daemon.ts:159 `bootstrap.refuse` 접근 시 `bootstrap === undefined`.
2. mock factory가 호출되는지 확인 (console.log 삽입) → **factory 정상 호출, keys 6개 모두 export 됨**.
3. 테스트 파일에서 `import * as bootstrapResolverModule from '../src/bootstrap-resolver.js'` 후 `typeof getBootstrap` 확인 → **`function`** (mock 적용됨).
4. `src/daemon.ts` 안에서 호출 직전 `typeof getCachedBootstrap` 확인 → `function`, `name=spy` (mock 적용됨), 그러나 **호출 결과 `undefined`**.
5. → `vi.fn()` 자체는 정상 mock인데 `mockReturnValue` 적용이 안 된 상태에서 호출. 즉 한 번 mockReturnValue 했다가 wipe 된 것.
6. `grep -n "resetAllMocks"` → `tests/daemon.test.ts:76` `vi.resetAllMocks()` (beforeEach 안). **확정**.

## 왜 main에선 안 보였나
main 브랜치의 daemon.ts에는 `if (cfg.mode === 'auth')` 분기 안에서만 `getCachedBootstrap` 호출. 테스트 config들은 `mode: 'auth'` 미설정 → 분기 우회 → mock 호출 site 비활성. v0.6.0에서 분기 제거하니 모든 cycle에서 호출되며 노출.

## Fix 패턴
`vi.resetAllMocks()` 사용하는 모든 spec 파일에서, 그 직후 `bootstrap-resolver` mock의 default를 다시 적용:

```ts
const bootstrapMocks = vi.hoisted(() => ({
  primeBootstrap: vi.fn(),
  getBootstrap: vi.fn(),
  peekCachedSnapshot: vi.fn(),
  bootstrapStatusLabel: vi.fn(),
  loadCachedSnapshotFromDisk: vi.fn(),
  resetBootstrapCacheForTest: vi.fn(),
}))
vi.mock('../src/bootstrap-resolver', () => bootstrapMocks)

beforeEach(async () => {
  // ...
  vi.resetAllMocks()
  // Re-establish bootstrap mock defaults wiped by resetAllMocks().
  bootstrapMocks.getBootstrap.mockReturnValue({
    snapshot: null, warning: null, refuse: false, status: 'ok',
  })
  bootstrapMocks.peekCachedSnapshot.mockReturnValue(null)
  bootstrapMocks.bootstrapStatusLabel.mockReturnValue('ok (1s ago)')
  bootstrapMocks.loadCachedSnapshotFromDisk.mockResolvedValue(null)
  bootstrapMocks.primeBootstrap.mockResolvedValue(undefined)
})
```
